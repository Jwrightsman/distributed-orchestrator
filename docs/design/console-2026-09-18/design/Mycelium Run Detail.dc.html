02

Two claims that must not read as one

The sealed manifest says these bytes are the bytes that were frozen. The envelope says who produced them, under which identity, with which model, checked by which validators. Neither says the output is correct, and the two do not combine into anything stronger. A reader who counts badges will conclude otherwise, so the design gives them different grammatical classes rather than a second badge.

RULE · DIFFERENT CLASS, NOT A SECOND BADGE

The manifest carries a state label because its state genuinely varies: sealed or legacy_live, and which one matters. The envelope carries a sentence, with no chip, no lamp and no colour, because its presence is not the interesting fact — its contents are. Two chips side by side is a row of ticks, and ticks get counted.

RULE · NO GROUP HEADER OVER BOTH

There is no INTEGRITY panel and no TRUST section anywhere in this design. A shared header is the thing that would combine them — it invites the reader to add up whatever sits underneath. They are two panels, one after the other, each carrying its own limit in its own footer.

RULE · THEY VARY INDEPENDENTLY

A sealed manifest with a legacy producer and no model digest is an ordinary run. So is an envelope over a legacy_live file list. Neither is evidence for the other, and no layout may imply that one being present improves the other.

04

The ledger chain, passing

A green tick here would be exactly the kind of lie this project has spent twenty-six pull requests refusing. So the passing state is not green: it is ordinary ink, a filled marker, a walked count, and the limit stated in the same box a person reads the verdict in. Green is reserved for PASS, connected and ok — an intact chain is none of those.

The limitation the repo asserts in a test rather than admits in a doc

A fully recomputed chain is undetectable. An operator with write access rewrites every entry and every link, and verification reports intact. That is not a caveat to put in a footnote — it is the meaning of the word on screen, so it sits under the verdict on every rendering of it.

07

The modal header, at a narrow width

Observed and deferred during the Phase 2 port, and it belongs to this design. .modal-head is a flex row that does not wrap; .modal-title carries min-width: 0 with no wrapping rule, so a long unbreakable identifier overflows its squeezed box; .modal-actions is flex-shrink: 0 and holds its width. The title runs under the buttons.
