# ADR 0010: Durable enrollment identity is separate from session incarnation

- Status: Accepted
- Date: 2026-08-25
- Decision scope: trusted-alpha contributor identity and attempt attribution

## Context

Mycelium previously had two worker identifiers: a human-readable `node_id` and
a process-local server-issued session. The deployment-wide `node_secret`
admitted every invited worker. It could not distinguish them after admission,
survive as per-node attribution across coordinator restart, or revoke one node
without rotating every worker.

The session design remains useful. A session identifies one live worker-process
incarnation, expires, and is deliberately lost on coordinator restart. It must
not be stretched into durable identity. Likewise, an attempt ID and nonce are
authority for one leased unit, not identity for a contributor.

## Decision

Mycelium separates four concepts:

```text
enrollment_id  immutable durable identity of one enrolled contributor
node_id        normalized human-readable label and display metadata
session_id     one process-local worker incarnation
attempt_id     authority for one leased execution unit
```

An enrollment is a server-generated random identifier stored in SQLite. Its
normalized node label is unique for the lifetime of the enrollment row,
including after revocation. Labels are not renameable in this protocol version.
A revoked or previously enrolled label cannot be claimed by a new enrollment.

Existing attempt, receipt, contribution, and quarantine rows receive nullable
enrollment fields. New enrolled work records the enrollment, label, and session
that received it. Historical rows with no enrollment stay explicitly
unattributed; migration does not infer an enrollment from their label.

## Credential and storage choice

Trusted-alpha enrollment uses a high-entropy bearer credential generated by
the stock worker with the standard-library cryptographic random generator. The
worker stores it in an identity file. The coordinator stores only a
domain-separated cryptographic digest and compares digests in constant time.

The credential, its plaintext rotations, the deployment admission secret,
session tokens, and attempt nonces are excluded from events, logs, operator
listings, and compatibility exports. Enrollment-list responses do not include
the credential digest.

Bearer enrollment is acceptable only inside the current small invited-alpha
boundary, over TLS or a private authenticated overlay. It proves possession of
one enrolled secret. It does not prove a physical machine, hardware, model
bytes, operator personhood, correctness, or uniqueness of a human participant.

## Bootstrap and returning registration

Registration has explicit paths:

- `bootstrap` requires the deployment admission secret and the worker's
  proposed enrollment credential. One immediate transaction creates the
  durable enrollment when both label and credential are unused. Repeating the
  same label and credential authenticates the same immutable enrollment.
  Neither the shared admission secret nor a different credential may overwrite
  an existing label.
- `returning` authenticates the node label and enrollment credential. It does
  not require the deployment admission secret and issues a fresh process-local
  session when needed.

Durable enrollment commits before session creation. Bootstrap convergence uses
the unique normalized label and proposed credential digest: repeating the same
pair returns the committed enrollment after an ambiguous response, while any
different pair conflicts. Rotation similarly treats the already committed
requested digest as a successful retry.

The stock worker writes a versioned, coordinator-scoped identity file before
bootstrap and adds the learned enrollment ID after registration. Writes use a
same-directory temporary file, flush, and atomic replacement. A kernel-held
cross-process creation lock makes concurrent first starts converge on one
credential instead of replacing each other's file. POSIX files are
mode `0600`, parents are restricted where supported, and dangerously
permissive files fail closed. Other platforms receive the operating system's
best-effort user-file protection; Mycelium does not claim to audit Windows
ACLs. Default filenames are hashes of normalized coordinator identities, not
untrusted URLs. Credentialed stock-worker joins require that explicit origin;
unauthenticated LAN discovery cannot select where enrollment bearers are sent.

## Sessions and attempt authority

An enrolled session record binds `enrollment_id`, `node_id`, session-token
digest, session ID, credential version, creation, last-seen, and expiry. Normal
heartbeat, poll, stream, drain, and result calls authenticate the session and
recover the enrollment from server state. They do not repeatedly present the
deployment admission secret.

Every authenticated operation checks the current durable enrollment row. A
missing, revoked, mismatched, or credential-rotated enrollment invalidates the
session and closes/reclaims its active attempts. Coordinator restart clears
sessions but leaves enrollments intact; the returning credential obtains a new
incarnation. A janitor independently revalidates live enrolled sessions every
30 seconds, which is the nominal maximum idle detection interval subject to
ordinary scheduler delay and durable-store availability. Store errors are
diagnosed and retried rather than interpreted as active or revoked state.

New enrolled attempts bind the enrollment, node label, session, and credential
version in addition to all existing task, execution, unit, contract, nonce,
lease, and output-budget fields. Settlement checks the durable enrollment in
the same SQLite write transaction. A session for enrollment B cannot settle an
active attempt assigned to enrollment A, even if it submits A's label.

An exact replay never creates another settlement. A current session for the
same active enrollment may recover the stored response for an already settled
attempt after an incarnation change; a different enrollment cannot.

## Revocation and rotation

Revocation changes one enrollment to `revoked` without deleting it. It is
durable and idempotent, blocks registration and future authenticated
operations, prevents settlement, and reclaims active leases through the
existing attempt lifecycle. Accepted receipts and contribution history remain.
Other enrollments and their credentials are unaffected.

Rotation atomically replaces the credential digest and increments the
credential version while preserving enrollment ID, label, attempts, receipts,
and contributions. Old credentials stop authenticating after commit. Existing
sessions are rejected and reclaimed on their next authenticated operation. The
operator command writes the new plaintext only to a requested identity bundle;
it never prints it. A prepared output is version-bound and can be resumed after
an ambiguous commit. If a committed output is lost, the operator rotates again
to a new credential because plaintext cannot be recovered from SQLite.

## Compatibility and migration

`node_enrollment_mode=required` is mandatory for trusted alpha. Local
development may use explicit `compat` mode. An old worker in required mode gets
a stable upgrade-required response. In compatibility mode its session has
`enrollment_id=null`; it is not shown or accounted as durable identity, and it
cannot claim any label already present in the enrollment table.

Schema initialization is additive and idempotent. Existing databases gain the
enrollment table and nullable attribution columns. No historical row is
rewritten to manufacture identity. New contribution summaries use enrollment
ID as the durable grouping key and keep the node label as metadata. New legacy
compatibility contributions are scoped to their session so label reuse does
not inherit history.

## Consequences

- One contributor can be revoked or rotated without changing every worker.
- Restart preserves attribution but invalidates live incarnation authority.
- Node labels remain useful to humans but are no longer durable trust keys.
- The coordinator and worker now have an operator-managed recovery secret.
- Backup and restore preserve enrollment digests and attribution in SQLite;
  worker identity files remain worker-owned secrets and are backed up
  separately by their operators. A point-in-time restore preserves only the
  revocations and rotations already captured in that snapshot, so operators
  must reconcile later offboarding and worker identity changes before reopening
  access.
- Contribution points remain non-monetary records of accepted compute, not
  correctness reputation.

## Deferred work

Public-key challenge-response, certificates, mTLS identity, signed provenance,
hardware/model attestation, Sybil resistance, permissionless admission,
marketplace identity, and global reputation are deliberately deferred. They
need different trust, recovery, privacy, and governance decisions. Typed
resource descriptors are also separate work and are not introduced here.

## Rejected alternatives

### Treat the shared admission secret as every node's identity

Rejected because it provides no individual attribution, revocation, or safe
label ownership after restart.

### Persist node sessions

Rejected because a session represents a live process incarnation and the
scheduler/queue it participates in is process-local. Restart must invalidate it.

### Infer historical enrollment from node labels

Rejected because labels were claimable under shared admission and cannot prove
which later enrollment produced an old row.

### Introduce PKI or attestation now

Rejected for this bounded trusted-alpha change. Bearer enrollment materially
improves incident containment without prematurely claiming machine identity,
signed provenance, or permissionless trust.
