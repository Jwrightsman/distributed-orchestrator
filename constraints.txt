# Exact versions that CI and the Docker image install.
#
#   pip install -r requirements.txt -r requirements-dev.txt -c constraints.txt
#
# requirements.txt says which versions the code supports; this file says which
# versions were actually tested. Until 2026-09-12 there was no such file, so
# every CI run and every image build installed whatever was newest that day.
# FastAPI 0.137 (June 2026) turned `app.routes` from a flat list into a tree.
# CI had it from its next run; the development machine kept FastAPI 0.135, so a
# test written against the flat list in #88 passed locally and failed in CI.
#
# The whole installed tree is pinned, not only the direct dependencies. Starlette
# arrives through FastAPI, which declares `starlette>=0.46.0` with no upper
# bound, and Starlette's TestClient switches HTTP library depending on whether
# `httpx2` is installed — both would drift under a direct-only pin.
#
# Versions come from a Linux Python 3.14 install. A package that is only pulled
# in on another platform (colorama on Windows, for example) is not listed and
# stays unpinned there; pip ignores constraints for packages it does not install.
#
# To upgrade: run the "Dependency Canary" workflow (it also runs weekly). It
# installs the newest releases requirements.txt allows, runs the full suite
# against them, and uploads `candidate-constraints.txt`. If it is green, replace
# the pins below with that file's contents and open a pull request; if it is red,
# the failure is the upgrade work. See CONTRIBUTING.md, "Dependencies".
