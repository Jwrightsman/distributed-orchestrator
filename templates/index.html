How it works

1

You pitch a task in plain English — "build a CSV deduplication script".

2

A planner splits it up into a few smaller jobs that can be worked on at the same time.

3

Volunteer machines build the pieces in parallel, each running a local AI model.

4

A reviewer assembles and grades the result, and the code is checked to see whether it actually runs.

What it can and can't do

~57% of 28 varied test tasks come back runnable and on-spec (95% confidence: 44–69%).
10/10 — a labelled bar chart, built correctly ten times out of ten.
2/10 — a playable Snake game. Tightly-coupled code is where a small model falls over, and that number is published for the same reason as the good one.
Every figure is reproducible from the repo, and the raw logs are committed alongside them.

Contributing a machine

Joining runs an AI model on your computer and uses spare CPU to build pieces of other people's tasks. It asks before it installs anything, and you stop it by closing the window. Joining is currently by invite — open an issue and you'll get the address.

$python join.py <address>
